# Как проверить работу самостоятельно

Все команды выполняются в PowerShell из каталога проекта:

```powershell
cd C:\Users\idv1102\Documents\deepseek-harness\default-workspace\siem-enricher
$env:PYTHONPATH = 'src'
$env:PYTHONIOENCODING = 'utf-8'
```

Порядок — от самого быстрого к самому полному. Каждый шаг независим.

## Шаг 1. Тесты — 30 секунд

```powershell
python -m unittest discover -s tests -t .
```

Ожидается:

```
Ran 121 tests in 6.5s
OK (skipped=3)
```

Три пропуска — тесты модели: в системном Python нет torch. Убедиться, что тесты не пустые:

```powershell
python -m unittest discover -s tests -t . -v 2>&1 | Select-String ' \.\.\. ok' | Measure-Object
```

Ожидается около 118 строк `... ok` — столько проверок реально выполнилось.

Те же тесты с моделью (интерпретатор с torch):

```powershell
& C:\Users\idv1102\PycharmProjects\PythonProject11\.venv\Scripts\python.exe -m unittest discover -s tests -t .
```

Ожидается: `Ran 121 tests` и `OK (skipped=1)` — пропуск теста конфигурации без PyYAML.

## Шаг 3. Посмотреть на одно событие глазами — 2 минуты

```powershell
Remove-Item var\state\provenance.db -ErrorAction SilentlyContinue
python tools\generate_sample_events.py --scenario exfiltration --count 3 --out var\demo.jsonl
python -m siem_enricher replay --input var\demo.jsonl --config config\config.local.json --limit 1
```

Удаление базы происхождения — чтобы демонстрация была воспроизводимой: сервис накапливает
историю между запусками, и глубина цепочки иначе растёт от прогона к прогону.

Предупреждение `Не удалось загрузить трансформер ... используются правила` в системном Python —
ожидаемо: там нет torch. Это и есть проверка деградации: сервис продолжает работать на правилах.

Ожидается: исходные поля события и рядом вычисленные `data_sensitivity`, `sensitivity_confidence`,
`provenance_chain`, `risk_score`, `risk_severity`, `policy_decision`, `policy_rule_ids`.

Сверьте вручную: откройте `var\demo.jsonl`, возьмите путь файла, действие и адрес получателя —
они должны попасть в обогащение. Если путь в событии — `C:\Общие\...`, класс должен быть открытым;
если `C:\Внутренние_документы\...` — служебным; если каталог `keys`/`secrets` или расширение
`.kdbx`/`.pem` — секретным.

## Шаг 4. Классификация по именам, включая гибридную схему — 2 минуты

Режим правил (работает без torch):

```powershell
python -m siem_enricher classify --config config\config.local.json `
  --path "C:\keys\id_rsa" --path "C:\Public\readme.md" --path "C:\Users\ivanov\Documents\паспорт_копия.pdf"
```

Ожидается: `secret`, `public`, `confidential`.

С моделью — здесь видно работу гибридной схемы (модель считает имя коммерческим,
но размещение в каталоге шаблонов делает документ открытым):

```powershell
& C:\Users\idv1102\PycharmProjects\PythonProject11\.venv\Scripts\python.exe -m siem_enricher classify `
  --config config\config.local.json --path "C:\Шаблоны\Шаблон_письма_клиенту.docx" --json 2>$null
```

Ожидается `"level": "public"`, `"method": "hybrid"` — приоритет организационного признака
(каталог шаблонов) над прогнозом модели. `2>$null` убирает из вывода полосу загрузки весов,
которую библиотека печатает в поток ошибок.

## Шаг 6. Цифры из ВКР — 5 минут

В главе 3 приведены: 120 событий, 4,87 событий/с, классы confidential 80 / secret 16 / public 16 /
internal 8, риск critical 26 / high 70 / medium 14 / low 10. Проверка:

```powershell
Remove-Item var\state\provenance.db -ErrorAction SilentlyContinue
python tools\generate_sample_events.py --scenario mixed --count 120 --out var\generated.jsonl
python -m siem_enricher replay --input var\generated.jsonl --config config\config.local.json --output var\enriched_check.jsonl
```

В сводке — 120 обработанных событий и 0 ошибок. Распределение классов:

```powershell
Select-String -Path var\enriched_check.jsonl -Pattern '"data_sensitivity": "confidential"' | Measure-Object
Select-String -Path var\enriched_check.jsonl -Pattern '"data_sensitivity": "secret"'       | Measure-Object
```

Ожидаемые значения для этого набора (проверено на чистом состоянии):

| Режим | confidential | secret | public | internal | critical | high | medium | low |
|---|---|---|---|---|---|---|---|---|
| с моделью (venv с torch) | **80** | **16** | **16** | **8** | 25 | 67 | 17 | 11 |
| только правила (системный Python) | 72 | 16 | 16 | 16 | 15 | 69 | 25 | 11 |

Классы `confidential`/`secret`/`public`/`internal` в режиме с моделью совпадают с числами
из главы 3 ВКР; различие по уровням риска между режимами — это и есть влияние классификации
на оценку риска. Уровни риска чувствительны к накопленной истории происхождения, поэтому
шаг начинается с удаления базы: без этого числа сдвигаются на единицы.

| `ModuleNotFoundError: siem_enricher` | не задан `PYTHONPATH` | `$env:PYTHONPATH = 'src'` |
