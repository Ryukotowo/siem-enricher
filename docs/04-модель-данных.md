# Модель данных и схема обогащения

## 1. Каноническое событие

Любое событие SIEM приводится к `NormalizedEvent` (`src/siem_enricher/models/event.py`).
Дальше все модули работают только с этой моделью — поэтому подключение новой SIEM сводится
к настройке сопоставления полей.

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | str | идентификатор события в источнике (или сгенерированный) |
| `timestamp` | datetime (UTC) | время события |
| `source` | str | коннектор-источник: `kafka`, `file_replay`, `elasticsearch`, `wazuh_indexer`, `api` |
| `action` | `ProvenanceAction` | каноническое действие: `read`, `copy`, `upload`, `encrypt`, `rename`, … |
| `host` | str \| None | узел (агент) |
| `user` | `UserInfo` | имя, домен, признак привилегированности |
| `process` | `ProcessInfo` | имя, путь, PID, командная строка, родительский процесс |
| `files` | `list[FileRef]` | объекты события: путь, имя, расширение, каталог, размер, SHA-256, действие |
| `remote` | `RemoteEndpoint` | IP, порт, URL, домен, направление, признак внешнего адреса |
| `rule` | `RuleRef` | правило SIEM: id, описание, уровень, MITRE-техники |
| `tags` | `list[str]` | метки события |
| `raw` | dict | исходное событие без изменений (для трассировки) |

### Сопоставление полей источников

Извлекатель (`extractor/metadata.py`) не привязан к конкретной схеме: используются
таблицы псевдонимов (`FIELD_ALIASES`) и контекстные правила для неоднозначных ключей
(`name`, `id`). Поддерживаются:

* **Wazuh / Sysmon** — `data.win.eventdata.targetFilename`, `sourceFilename`, `image`, `user`,
  `destinationIp`, `rule.id`, `rule.level`, `agent.name`;
* **Elastic ECS** — `file.path`, `process.name`, `user.name`, `host.name`, `event.action`, `url.full`;
* **произвольный JSON** — по тем же псевдонимам; при отсутствии совпадений событие
  обогащается без файлов (с предупреждением).

Особые случаи, реализованные осознанно:

| Случай | Решение |
|---|---|
| `DOMAIN\user` и `user@domain` | разделяются на домен и имя (`split_account`) |
| `agent.ip` (адрес самого агента) | не считается получателем данных (`LOCAL_ADDRESS_SEGMENTS`) |
| путь в текстовом поле вида `file.xlsx (read)` | хвост-маркер действия отбрасывается (`ACTION_SUFFIX_RE`) |
| два пути подряд `C:\a\b.xlsx E:\leak.xlsx` | находятся оба (пошаговое сканирование) |
| системные пути `C:\Windows\…` | отбрасываются при `extractor.drop_system_paths = true` |

## 2. Поля обогащения

Обогащённый документ — плоская структура, совместимая с корреляцией в SIEM: исходные поля
сохраняются, к ним добавляются новые (префиксов не требуется, конфликты имён исключены).

| Поле | Тип | Смысл |
|---|---|---|
| `data_sensitivity` | str | класс конфиденциальности события: `public`/`internal`/`confidential`/`secret` |
| `data_sensitivity_rank` | int | ранг класса (0…3) — удобно для сравнений в правилах |
| `data_sensitivity_ru` | str | расшифровка класса на русском |
| `sensitivity_confidence` | float | уверенность классификации (0…1) |
| `sensitivity_method` | str | `ml` / `heuristic` / `hybrid` / `default` / `none` |
| `sensitivity_model_version` | str | версия модели (для воспроизводимости выводов) |
| `sensitivity_reason` | str | текстовое обоснование (вклад модели и правил) |
| `data_sensitivity_by_file` | list | оценка по каждому объекту события с обоснованием |
| `provenance_chain` | list | шаги происхождения основного объекта (плоский список) |
| `provenance_chains` | list | цепочки по каждому объекту: глубина, время, внешние адреса |
| `provenance_depth` | int | глубина цепочки (число шагов) |
| `external_destinations_count` | int | число внешних адресатов, зафиксированных для объекта |
| `external_destinations` | list | сами адреса (URL/домен/IP) |
| `risk_score` | float | оценка риска 0…1 |
| `risk_severity` | str | `low`/`medium`/`high`/`critical` |
| `risk_components` | dict | вклад каждой компоненты риска (для объяснения и отладки) |
| `risk_explanation` | list | человекочитаемое объяснение оценки |
| `policy_decision` | str | итоговое решение: `allow`/`tag`/`alert`/`mask`/`block` |
| `policy_actions` | list | сработавшие правила и результаты их действий |
| `policy_rule_ids` | list | идентификаторы сработавших правил (для корреляции и метрик) |
| `files_count` | int | число объектов в событии (основа компоненты «объём») |
| `enrichment` | dict | служебные сведения: версии, длительность, предупреждения, замаскированные поля |

## 4. Расчёт оценки риска

Оценка — взвешенная сумма нормированных компонент с усилением опасных сочетаний
(`src/siem_enricher/enricher/risk.py`):

```
score = min(1, ( w_класс·W[класс] + w_увер·уверенность + w_действие·M[действие]
               + w_внеш·[внешний адрес] + w_привил·[привилегированный пользователь]
               + w_объём·насыщение(число файлов) ) · усилитель)
```

| Компонента | Вес | Значение |
|---|---|---|
| класс конфиденциальности | 0.45 | `public` 0.05, `internal` 0.35, `confidential` 0.70, `secret` 1.00 |
| уверенность классификации | 0.15 | 0…1 |
| действие | 0.20 | `read` 0.25, `copy` 0.50, `archive` 0.70, `encrypt` 0.85, `upload`/`send` 1.00 |
| внешний адресат | 0.10 | приватные адреса не учитываются |
| привилегированный пользователь | 0.05 | по признаку учётной записи |
| объём | 0.05 | насыщение: `log2(1+N)/log2(33)` |

Усилители: конфиденциальные данные + внешний адрес ×1.15; упаковка перед внешней передачей ×1.10;
перемещение объекта класса `secret` ×1.10. Пороги уровней: `medium` 0.30, `high` 0.60,
`critical` 0.85 (настраиваются в `config/*.json` → `risk.thresholds`).

Примеры значений: чтение открытого файла ≈ 0.17 (`low`); копирование кадрового документа ≈ 0.60
(`high`); отправка архива с персональными данными во внешний адрес ≈ 0.83…0.90 (`high`/`critical`).

## 5. Provenance-цепочка

Шаг цепочки содержит: время, действие, путь, субъекта (пользователь/процесс), узел, событие,
направление (`self`/`inbound`/`outbound`), связанный объект (второй файл или внешний адрес)
и текстовое пояснение.

Направления:

| Направление | Когда возникает | Пример |
|---|---|---|
| `self` | действие субъекта над файлом | `chrome.exe` → `upload` файла |
| `inbound` | файл получен из другого объекта/адреса | копия получена из `C:\HR\…` |
| `outbound` | файл ушёл в другой объект/адрес | файл скопирован на `E:\…`, отправлен на `dropbox.com` |

Окно анализа: `provenance.ttl_seconds` (по умолчанию 7 суток) отсчитывается от времени
события; при запросе цепочки без события используется текущее время (`as_of`).

## 6. Версионирование схемы

* `version.py` → `VERSION` (версия ПС) и `ENRICHMENT_SCHEMA_VERSION` (версия схемы обогащения);
* в каждом обогащённом событии есть `enrichment.schema_version` и `enrichment.enricher_version`,
  поэтому по журналу можно понять, какой версией получены поля;
* при несовместимом изменении набора полей версия схемы увеличивается, старые события остаются
  интерпретируемыми.
