# Тестирование и измерения

## 1. Как запускать

```powershell
# Все тесты (стандартная библиотека, без внешних зависимостей)
python -m unittest discover -s tests -t . -v

# Через pytest (если установлен; тесты совместимы)
pytest -q

# Сквозной сценарий с ML-моделью и без неё
python tools\smoke_pipeline.py --config config\config.local.json
python tools\smoke_pipeline.py --config config\config.local.json --force-heuristic

# Полная проверка проекта (линтер, типы, тесты, сценарий, конфигурации)
powershell -ExecutionPolicy Bypass -File scripts\check_all.ps1
```

## 3. Сквозной сценарий (18 проверок)

`tools/smoke_pipeline.py` генерирует 15 событий (сценарий `mixed`) и проверяет поведение
конвейера на них:

| № | Проверка |
|---|---|
| 1 | все события обогащены (класс, риск, цепочка, действие) |
| 2 | файлы с ключами и хранилищами секретов → `secret` |
| 3 | открытые файлы → `public` |
| 4 | кадровые документы → `confidential` |
| 5 | POL-001 срабатывает при отправке конфиденциального файла во внешний адрес (риск high/critical) |
| 6 | маскирование применено: путь заменён на `sha256:…`, список полей зафиксирован |
| 7 | POL-006 срабатывает при копировании на съёмный носитель |
| 8 | POL-007 срабатывает при шифровании/переименовании файлов |
| 9 | POL-003 срабатывает при массовом обращении (13 файлов) |
| 10 | POL-002 → решение `block` со статусом `simulated` (`dry_run`) |
| 11 | цепочка происхождения накапливается между событиями |
| 12 | для файла на съёмном носителе зафиксирован источник |
| 13 | метрики Prometheus заполняются |
| 14 | экспорт метрик формируется |
| 15 | извлекатель не создаёт путей с «мусорными» суффиксами |
| 16 | локальный адрес агента не попадает в список внешних получателей |
| 17 | внешний адрес из события попадает в цепочку и учитывается в риске |
| 18 | обращение к ранее отправленному файлу учитывает внешний адрес из цепочки |

Сценарий выполняется и с ML-моделью, и в режиме только правил — в обоих случаях 18 из 18.

## 5. Методика измерений (для повторения в ВКР)

1. Зафиксировать конфигурацию: `config/config.local.json`, `ml.type`, `device=cpu`, `batch_size=16`.
2. Сгенерировать поток: `python tools/generate_sample_events.py --scenario mixed --seed 42`.
3. Прогреть модель (первый запуск включает загрузку весов ~10–20 с) и выполнить прогон;
   замер задержки берётся из поля `enrichment.duration_ms` каждого события.
4. Повторить 3–5 раз, взять медиану (первый прогон отбросить).
5. Для оценки качества модели: `ml/training/evaluate_transformer.py` (артефакты
   `var/metrics_transformer.json`, `var/metrics_hybrid.json`); обязательно указывать,
   на каких данных получены метрики (обучающие/синтетические/отложенные).

## 6. Что не покрыто тестами (честные границы)

| Область | Причина | Как проверить вручную |
|---|---|---|
| HTTP-слой FastAPI (`/v1/*`) | **проверен** смоуком `scripts/http_smoke.ps1`: 9 эндпоинтов, старт за 1,5 с | повтор: `powershell -ExecutionPolicy Bypass -File scripts\http_smoke.ps1` |
| Стенд на открытой SIEM (профиль `siem`) | требует Docker и образ OpenSearch; локально не запускался | `docker compose --profile siem up --build`, затем `tools/seed_opensearch.py --verify` |
| Коннекторы Kafka/Elasticsearch «вживую» | требуют брокера/кластера | `docker compose up`, профиль `producer` (Kafka); Elasticsearch — против тестового кластера |
| Wazuh Active Response | требует развёрнутого Wazuh API | исполнитель покрыт проверкой выбора (`test_blocker_selection`), реальный вызов — вручную |
| Нагрузочное тестирование | вне рамок работы | `locust` из `requirements-dev.txt`, либо повторные прогоны `replay` |

Эти границы зафиксированы осознанно: ядро (7 модулей) покрыто полностью, а внешние
интеграции подключаются конфигурацией и проверяются на стенде.

## 7. Регрессионная защита

Отдельно отмечены проверки, защищающие найденные в ходе разработки дефекты:

* «мусорный» суффикс действия в пути (`file.xlsx (read)`) — тесты извлекателя и проверка №15;
* адрес агента как внешний получатель — тест `test_agent_address_is_not_remote_endpoint` и №16;
* порядок «условия → действия» в политиках — `test_masking_is_applied_after_all_conditions`;
* семантика `ml.type=transformer` (без гибрида) — тесты классификатора и оценки;
* чтение CSV с BOM — скрипты обучения используют `utf-8-sig`.
