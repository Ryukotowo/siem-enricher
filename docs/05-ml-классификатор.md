# ML-классификатор конфиденциальности

## 1. Постановка задачи

По **имени файла** (короткий текст, до 64 токенов) определить категорию документа,
которая затем отображается на класс конфиденциальности.

Категории модели (6, из НИР): `personal`, `banking`, `commercial`, `ip`, `official_internal`, `public`.

Отображение на классы (`config/sensitivity_labels.json` → `model_categories`):

| Категория | Класс | Основание |
|---|---|---|
| `personal` | confidential | персональные данные (152-ФЗ) |
| `banking` | confidential | банковская тайна |
| `commercial` | confidential | коммерческая тайна |
| `ip` | confidential | интеллектуальная собственность, ноу-хау |
| `official_internal` | internal | для служебного пользования |
| `public` | public | открытая информация |
| — | **secret** | присваивается только правилами: `id_rsa`, `.kdbx`, `.pem`, `.env`, каталоги `keys/`, `secrets/` |

Класс `secret` в модели отсутствует осознанно: криптоматериалы и хранилища паролей надёжнее
определять детерминированно, чем учить модель на редких примерах.

## 2. Данные

| Источник | Объём | Назначение |
|---|---|---|
| Датасет НИР `filenames_mixed_dataset.csv` (колонки `text,label`) | 1599 имён файлов | обучение и оценка модели |
| Генератор событий `tools/generate_sample_events.py` (эталонная разметка) | 430 объектов | проверка сквозного сценария, устойчивость к реальным событиям |

Сборка датасета: `ml/training/build_dataset.py` → `ml/data/processed/files.csv`
(колонки `path,text,label,source`, где `source` = `csv` или `generator` — для раздельной оценки).

## 3. Модель

| Параметр | Значение |
|---|---|
| Базовая модель | `bert-base-multilingual-cased` (mBERT), `BertForSequenceClassification` |
| Число классов | 6 |
| Максимальная длина | 64 токена (имя файла) |
| Обучение | `ml/training/train_transformer.py`: 5 эпох, batch 16, lr 2e-5, стратифицированное деление 80/20, seed 42 |
| Артефакт | каталог `ml/artifacts/sensitivity_transformer/` (`config.json`, `model.safetensors`, `tokenizer.json`, `label_encoder.pkl`, `metrics.json`) |
| Инференс | CPU, `batch_size` 16, ~10–30 мс на объект (mBERT), автоматический выбор CUDA при наличии |

Формат артефакта и порядок воспроизведения — `ml/README.md`.

## 4. Гибридная схема (ML + правила)

Реализация: `src/siem_enricher/ml/hybrid.py`. Алгоритм объединения оценок:

| Ситуация | Решение | Настройка |
|---|---|---|
| Признак размещения/пометы повышает класс относительно модели | берётся класс признака | `hybrid_policy_override`, `hybrid_policy_override_min_weight` |
| Признак размещения = `public` (общедоступный каталог, readme, шаблон) | класс понижается до `public` — организационное решение сильнее прогноза | то же |
| Правила содержания выше класса модели и уверенность правил ≥ порога | класс повышается | `hybrid_rule_min_confidence` (0.5) |
| Правила содержания ниже класса модели, модель неуверена (≤ 0.85) | класс понижается | `hybrid_downgrade_min_rule_confidence`, `hybrid_downgrade_max_model_confidence` |
| Классы совпали | уверенности объединяются (вес 0.6 у «победителя») | `hybrid_confidence_blend` |
| Слабый признак размещения (`Projects/`, `backup/` → internal) | класс **не понижается** — секреты могут лежать в любом каталоге | — |

Причина решения записывается в `data_sensitivity_by_file[*].reason`, поэтому в SIEM видно,
почему объект отнесён к классу (вклад модели и вклад правил).

## 5. Метрики качества

Измерения выполнены скриптом `ml/training/evaluate_transformer.py`
(артефакты: `var/metrics_transformer.json`, `var/metrics_hybrid.json`).

### 5.1 Модель на «родном» датасете (1599 имён, `source=csv`)

| Уровень | Accuracy | F1 macro | F1 weighted |
|---|---|---|---|
| Категории модели | **0.952** | 0.949 | 0.949 |
| Классы конфиденциальности | **0.976** | 0.970 | — |

Значение является **верхней оценкой**: этот датасет использовался при обучении модели.
Честная оценка получается стратифицированным делением в `train_transformer.py`
(80 % обучение / 20 % контроль, метрики сохраняются в `metrics.json`).

### 5.2 Модель и гибрид на синтетических событиях (430 объектов, `source=generator`)

| Схема | Accuracy (классы) | F1 macro (классы) |
|---|---|---|
| Только модель | 0.463 | 0.246 |
| **Гибрид (модель + правила)** | **0.772** | **0.561** |

Это ключевой результат работы: на именах, нетипичных для обучающей выборки
(«Зарплатная_ведомость_2025.xlsx», «Паспортные_данные_сотрудников.xlsx», «Ключи_подписи.pem»),
модель ошибается часто, а гибридная схема восстанавливает класс за счёт организационных
признаков (каталоги `HR`, `Бухгалтерия`, `keys`, расширения `.pem`, `.kdbx`).

Категорийные метрики на синтетических событиях **не показатели**: категория для них назначена
отображением из класса конфиденциальности (класс → категория), а не экспертной разметкой.

### 5.3 Гибрид на «родном» датасете

| Схема | Accuracy (классы) | F1 macro |
|---|---|---|
| Только модель | 0.976 | 0.970 |
| Гибрид | 0.854 | 0.620 |

Снижение объяснимо и ожидаемо: часть файлов категории `official_internal` имеет в имени явную
пометку конфиденциальности (`…_confidential.docx`), и правила **осознанно** повышают их класс.
Для системы защиты данных это предпочтительный тип ошибки: пропуск чувствительного документа
опаснее его избыточной классификации (смещение в сторону защиты).

### 5.4 Типовые ошибки (анализ из отчёта оценки)

| Ошибка | Пример | Причина |
|---|---|---|
| `banking` → `commercial` | `secret_client_list.xlsx` | пересечение лексики банковской и коммерческой тайны |
| `official_internal` → `public` | `prazdnichny_grafik_2025.docx` | модель ориентируется на «праздничный график», каталог не указан |
| `commercial` → `personal` | имена с ФИО | шаблоны имён документов пересекаются |
| категория вне карты | новая категория в модели | класс по умолчанию + метрика `ml_fallback_total{reason="unknown_category"}` |

## 6. Поведение при отказах

| Ситуация | Поведение | Наблюдаемость |
|---|---|---|
| Артефакт модели отсутствует | работают только правила | `ml_fallback_total{reason="artifact_missing"}` |
| Нет `torch`/`transformers` | то же | `reason="ImportError"` |
| Категория не сопоставлена классу | класс по умолчанию (`ml.default_level`) | `reason="unknown_category"` |
| Ошибка инференса на объекте | событие обогащается без ML-оценки этого объекта | `enrichment.warnings` |

Деградация никогда не приводит к потере события: конвейер продолжает работу,
а причина фиксируется в метриках и предупреждениях.

## 7. Что можно улучшить (направления развития)

1. **Честная оценка качества**: дообучение с отложенной выборкой и публикация матрицы ошибок.
2. **Устойчивость к внеобучающим именам**: аугментация (транслит/кириллица, опечатки, цифры года),
   добавление в обучение синтетических имён из генератора событий.
3. **Метрика, ориентированная на защиту**: доля пропущенных конфиденциальных объектов
   (false negative rate по классам `confidential`+`secret`) — важнее общей accuracy.
4. **Контекст в признаках**: обучение на строке «имя + каталог» (в конфигурации уже есть
   `ml.text_template`), что требует переобучения и нового датасета.
5. **Квантизация/ONNX** для снижения задержки на слабых узлах.
