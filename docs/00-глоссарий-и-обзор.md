# Обзор: термины, место в конвейере SIEM, границы ПС

## 1. Термины

| Термин | Значение в работе |
|---|---|
| **SIEM** | система управления событиями и информацией о безопасности (сбор, нормализация, корреляция, алертинг) |
| **Событие** | запись о действии в инфраструктуре: обращение к файлу, запуск процесса, сетевое соединение |
| **Обогащение (enrichment)** | добавление к событию сведений, которых в нём нет, но которые нужны для корреляции и реагирования |
| **Сервис-обогатитель** | отдельный сервис, который читает поток событий SIEM, дополняет их и возвращает обратно |
| **Класс конфиденциальности** | категория чувствительности объекта: `public` → `internal` → `confidential` → `secret` |
| **Provenance (происхождение)** | прослеживаемая история объекта: как он появился, кто и что с ним делал (чтение, копирование, отправка) |
| **Цепочка происхождения** | упорядоченная по времени последовательность действий над конкретным файлом |
| **Риск-скоринг** | числовая оценка опасности события (0…1) и её уровень: `low`/`medium`/`high`/`critical` |
| **Политика** | декларативное правило «условие → действие»: маскирование, алертинг, блокировка, тег |
| **Маскирование** | замена чувствительного значения (пути, имени пользователя) хешем/псевдонимом в обогащённом событии |
| **Признак размещения** | детерминированный признак (каталог, гриф в имени, расширение), отражающий организационное решение о классе |
| **Признак содержания** | признак, указывающий на смысл документа (паспорт, зарплата, договор) |
| **dry-run** | режим, в котором решения фиксируются, но блокирующие действия не выполняются |

## 2. Место сервиса в конвейере обработки событий SIEM

```
 источники событий                СЕРВИС ОБОГАЩЕНИЯ                    SIEM-платформа
┌────────────────┐        ┌──────────────────────────────┐        ┌──────────────────┐
│ агенты/агенты  │        │ 1. Коннектор к SIEM (Kafka)  │        │ корреляция       │
│ EDR, DLP, ОС   │        │            ↓                 │        │ правила, алерты  │
│ файловые шарды │        │ 2. Извлекатель метаданных    │        │ дашборды, отчёты │
└───────┬────────┘        │            ↓                 │        └────────┬─────────┘
        │                 │ 3. ML-классификатор          │                 ↑
        │  поток событий  │    (имя файла + правила)     │   обогащённые   │
        └────────────────►│            ↓                 │   события       │
                          │ 4. Provenance (граф)         │                 │
                          │            ↓                 │                 │
                          │ 5. Обогатитель:              │                 │
                          │    data_sensitivity,         │                 │
                          │    provenance_chain,         │                 │
                          │    risk_score                │                 │
                          │            ↓                 │                 │
                          │ 6. Применение политик        │                 │
                          │    (маскирование, алерт,     │                 │
                          │     блокировка)              │                 │
                          │            ↓                 │                 │
                          │ 7. Обратный коннектор ───────┼─────────────────┘
                          └──────────────────────────────┘
```

Ключевая идея: сервис **не заменяет** SIEM и не требует её доработки. Он подключается к уже
существующему потоку событий (в работе — Kafka) и возвращает обогащённые события в тот же
поток, где SIEM коррелирует их обычными средствами.

## 3. Границы программного средства

**Что делает ПС:**

* читает события из Kafka (или из файла/индекса Elasticsearch);
* извлекает сущности события: файлы, пути, процессы, пользователей, сетевые адреса, правило SIEM;
* определяет класс конфиденциальности объекта: ML-модель по имени файла + детерминированные
  правила по каталогу размещения, пометкам и расширению;
* строит и хранит цепочки происхождения объектов, отслеживая копирование, архивирование,
  отправку во внешние адреса;
* рассчитывает оценку риска и уровень критичности события;
* применяет декларативные политики: маскирование, алертинг, теги, блокировку (в `dry_run`/`live`);
* ведёт журнал аудита решений и отдаёт метрики Prometheus;
* возвращает обогащённое событие в SIEM.

**Что ПС не делает (и почему):**

* **не анализирует содержимое файлов** — в событии SIEM содержимого нет, а его получение
  потребовало бы доступа к самим данным и создало бы новый канал утечки;
* **не заменяет DLP-агент** — ПС работает на уровне событий, а не перехвата операций ввода-вывода;
* **не является средством разграничения доступа** — блокировка реализована как интеграция
  с внешними системами (SOAR/EDR/Active Response), сам сервис не управляет правами;
* **не хранит содержимое событий дольше TTL** — хранилище происхождения хранит только метаданные
  (узлы, рёбра, время) и очищается по TTL (по умолчанию 7 суток).

## 4. Кому и зачем нужен результат

| Роль | Что получает |
|---|---|
| Аналитик SOC | события с готовым классом конфиденциальности и цепочкой происхождения: видно, что утекло и как |
| Инженер ИБ | декларативные политики, журнал аудита решений, метрики, режим `dry_run` для безопасного внедрения |
| Владелец данных | автоматическое выявление обращений к чувствительным документам и попыток их выноса |
| Исследователь | воспроизводимый стенд: генератор событий, датасет, метрики, тесты |

## 5. Отличия от существующих подходов

| Подход | Ограничение | Что делает ПС |
|---|---|---|
| Правила SIEM по именам файлов | хрупкие регулярки, много ложных срабатываний | ML-модель по имени + правила только для организационных признаков |
| DLP-система | требует агентов и доступа к содержимому, отдельный контур | работает по событиям SIEM, содержимое не требуется |
| Скрипт-обогатитель в SIEM | привязан к конкретной SIEM, нет provenance и политик | сервис с коннекторами, граф происхождения, политики, аудит |
| Только классификация | нет ответа на вопрос «как данные вышли» | provenance-цепочка + риск-скоринг + действия |
